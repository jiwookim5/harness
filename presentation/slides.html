과제 목표

"AI가 말한 것"과 "확인된 것"을 분리한다

이 과제의 핵심은 도구를 쓰는 게 아니라, AI 출력을 그대로 믿지 않는 구조를 직접 만드는 것이었다.

세 가지 축

  • 강사 Repository → 개인 Private Repo로 Harness v0 구축
  • 공통 예제와 다른 신규 CVE 1개 이상 분석
  • 분석 중 발견한 문제를 Harness v1으로 개선

지켜야 했던 원칙

  • AI 출력 자체는 Evidence가 아니다
  • 결론은 공식 Advisory·Patch Diff·실제 실행 로그로만 확정
  • Target은 항상 127.0.0.1 / 격리 Docker로 한정

Harness 구조

D1 → D2 → D3, 한 번 만들면 CVE마다 재사용

harness/ 아래 공통 정책·템플릿·검증기를 두고, cves/<CVE-ID>/ 아래 CVE별 산출물을 쌓는 구조.

CVE Intake→ 공식 Source Map→ Patch Diff→ Root Cause→ CWE→ Human GO→ Observation→ Evidence Review→ Report

역할 분리

  • AI: Source 탐색, 초안, Tool 실행까지만
  • 학생: Scope 승인, GO <control_id>, Evidence·최종 결론 확정

자동 Gate

  • npm run check -- D1|D2|D3 <CVE-ID>
  • FACT는 Source Ref 없으면 REVISE
  • Same-Control hash 불일치 시 REVISE

CVE-2021-41773 — Apache httpd Path Traversal

ap_normalize_path()의 스캔 순서 버그로, .%2e 세그먼트의 디코딩된 두 번째 문자가 재검사를 피해가면서 ..가 결과에 남는다. CWE-22.

CVE #2 · 신규 분석

CVE-2021-43798 — Grafana Path Traversal

Go filepath.Clean()은 상대 경로에선 선행 ..를 안 지운다. 내장 plugin 라우트(/public/plugins/<id>/)가 이 값을 그대로 Join해서 plugin 디렉터리 밖으로 나간다. CWE-22.

Target버전HTTPmarker
127.0.0.1:83008.2.6200노출됨
127.0.0.1:83018.2.7404차단

41773과의 차이

  • 별도 미보호 설정 불필요 — 기본 설치가 바로 취약
  • 진입점(plugin 경로)을 추측 안 하고 실제 이미지를 inspect해서 확인
  • Control을 처음부터 단일 lifecycle로 설계 (41773의 시행착오 반영)

Same-Control 원칙

"같은 조건에서 비교했다"를 해시로 증명

두 CVE 모두 취약/조치 버전에 완전히 동일한 input·request·criteria·timeout을 적용했는지 sha256으로 대조했다.

input_sha256 / request_sha256 / criteria_sha256 → 두 Target에서 동일해야 Same-Control 성립

둘 다 통과

하나라도 다르면 "비교 자체가 무효"로 REVISE — 실제로 이 규칙 덕에 timeout 미설정 같은 누락을 잡아냈다.

Evidence 승인 구조

Raw → 학생 REVIEWED/report_eligible 승인 → Masked(강의·제출용) → 다시 학생 승인 → 보고서 인용 가능

Harness v1 개선 · 발견한 문제

분석하다가 실제로 부딪힌 문제 3건

Blocker 1 문제

macOS 기본 bash(3.2)가 연관 배열 미지원 → Lab 스크립트가 즉시 죽음

개선

case 문으로 재작성, invariants.md에 호환 규칙 추가

Blocker 2 문제

전역 .gitignore가 .env를 시크릿으로 오인, 비밀 아닌 digest 설정이 커밋 안 됨

개선

digests.env로 이름 변경, 관련 규칙 문서화

Blocker 3 문제

자동 Gate 검증기가 CVE ID를 하드코딩 — 신규 CVE는 검증 자체가 불가능했음

개선

checkDay(root, day, cveId)로 매개변수화, 기본값 유지로 하위 호환

Harness v1 개선 · 검증

고치고 나서 "재실행"으로 확인

셋 다 고친 뒤 같은 입력으로 다시 돌려서 결과가 그대로인지 확인 — 개선이 다른 걸 깨뜨리지 않았다는 증거.

npm test → 34 pass, 0 fail
npm run check -- D1 → DAY=D1 CVE=CVE-2021-41773 DECISION=GO
npm run check -- D1 CVE-2021-43798 → DAY=D1 CVE=CVE-2021-43798 DECISION=GO

CVE ID 매개변수화 전에는 두 번째 명령 자체가 불가능했다 — 검증기가 항상 첫 번째 CVE 경로만 읽었기 때문.
