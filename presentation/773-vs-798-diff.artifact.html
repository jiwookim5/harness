차이 2 · 근본 원인 (코드 레벨)

어디서 ".."이 살아남았나

둘 다 경로 정리(clean/normalize) 단계의 결함이지만, 결함이 생기는 지점이 다르다.

41773 — 디코딩 타이밍 문제

.. 판별이 "슬래시 직후"에서만 일어나는데, .%2e의 두 번째 문자(%2e)는 그 판별이 끝난 뒤에 별도 분기에서 .로 디코딩된다. 디코딩된 문자는 재검사되지 않는다.

GET /pub/.%2e/lab-secret/marker.txt

43798 — 상대 경로 Clean 문제

Go filepath.Clean()은 상대 경로에서 선행 ..를 제거하지 않는다. 사용자 입력을 상대 경로 그대로 Clean한 뒤 filepath.Join()이 다시 Clean을 수행하면서 plugin 폴더 밖으로 경로가 축약된다.

filepath.Clean(web.Params(c.Req)["*"])

41773 → 43798 · 무엇을 그대로 가져왔나

공통 harness는 그대로 재사용했다

방법론 자체는 바꾸지 않았다. 41773에서 검증한 구조를 43798에 그대로 적용했다.

공식 Source Map→ FACT/INFERENCE/UNKNOWN 태그→ Same-Control(hash 동일성)→ 사람 GO 승인→ Evidence Review

그대로 유지

  • Source 우선순위: GHSA/공식 Advisory → CVE 공식 레코드 → 수정 commit
  • input_sha256·request_sha256·criteria_sha256로 "같은 조건 비교" 증명
  • 127.0.0.1 loopback Docker Lab, 파괴적 동작 금지

41773의 시행착오가 반영된 부분

  • macOS bash 3.2 호환 문제를 겪어서, 43798은 처음부터 호환되게 작성
  • Control을 버전별로 쪼갰다 다시 합친 경험 → 43798은 처음부터 단일 lifecycle로 설계
  • 진입점을 추측하지 않고 이미지를 직접 inspect하는 습관이 굳어짐
