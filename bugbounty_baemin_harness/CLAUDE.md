## 이 프로젝트의 특성

1. **벤더와의 계약 관계**: 파인더갭 프로그램 규칙이 우선
2. **타임라인 민감**: 공개 취약점은 타이밍이 중요 (선착순)
3. **증거의 중요성**: 보상을 받으려면 명확한 PoC 필수
4. **Responsible Disclosure**: 취약점 발견 후 보고 전 배달의민족 대응 시간 필요 (파인더갭 규칙 참고)

## 작업 흐름

### Preflight (매 세션마다)

- scope.md의 Scope 승인 상태 확인
- 파인더갭 대시보드의 현재 in-scope 목록 확인 (변경됨?)
- 이미 리포트된 취약점 목록 확인 (중복 피하기)

### Recon

- 표준 정찰: 포트스캔, 헤더 분석, 기술스택 식별
- 수동 웹사이트 탐색 (화면 UI에 보이는 기능만)
- 무제한 자동스캔은 금지 (Nuclei, Burp Pro 자동 공격 등)

### Finding & PoC

- 각 취약점마다 Control ID + 명령 + stdout/stderr 로깅
- PoC 작성 시 "실제 배달의민족 데이터를 수정하지 않기" 원칙 유지
- 에러 메시지, 스크린샷, curl 요청/응답 전부 보존

### Reporting

- finding-summary.md: 각 취약점 1줄 요약 + CVSS/CWE
- report.md: 전체 세션 종합 보고서
- 보상 신청 전 evidence 폴더의 모든 파일 double-check

## 금지 행동 (한 번 더 강조)

```
❌ 데이터 삭제/수정 (user data, config 변경 등)
❌ 다른 사용자 계정 탈취/변조
❌ 지속성 달성 (웹셸, cron, backdoor)
❌ DoS/DDoS (리소스 고갈)
❌ 결제 시스템 직접 테스트 (금전 거래)
❌ 사실 위반 (거짓 취약점 리포트)
```

이 중 하나라도 하려고 하면, AI는 "허용되지 않는 행동"이라고 거절해야 합니다.
