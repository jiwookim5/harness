# Scope — 배달의민족 버그바운티

## 대상(In-Scope)

- **플랫폼**: 파인더갭(FinderGap) 공식 버그바운티 프로그램
- **회사**: 배달의민족(Coupang Eats Korea)
- **프로그램 규칙**: [파인더갭 공식 안내 페이지](https://www.findergap.io)에 명시된 규칙을 따른다
- **테스트 대상**: 파인더갭 대시보드에서 명시한 in-scope 호스트/도메인만

### 예상 대상 범위 (파인더갭 공식 가이드 기준)

- `baemin.com` 및 주요 서브도메인
- 배달의민족 관련 서비스 도메인 (파인더갭에서 허가한 것만)
- 모바일 앱 내 API 엔드포인트 (동의된 호스트만)

> **중요**: 정확한 in-scope 호스트 목록은 파인더갭 대시보드에서 프로그램 상세 보기 → 스코프 섹션을 확인해야 한다.
> 이 문서의 목록은 참고용이며, 실제 테스트 시작 전에 파인더갭 공식 스코프를 확인할 것.

---

## Out of Scope (금지)

### 테스트 금지 대상

- In-scope에 명시되지 않은 모든 호스트/IP/도메인
- 3rd party 서비스(AWS, 결제 시스템 등) — 배달의민족 자체만
- 다른 참가자의 발견사항 또는 이미 리포트된 취약점 (파인더갭에서 확인 가능)

### 행동 제한

- **파괴적 행동 금지**: 데이터 삭제, 수정, 손상, 서비스 마비
- **지속성 시도 금지**: 웹셸, 백도어, cron job, 계정 생성 등
- **Reverse Shell 금지**: 외부로 나가는 연결
- **Credential 수집 금지**: 취약점 테스트용 계정/토큰 확보는 예외
- **무제한 자동화 금지**: Nuclei, Burp Suite 자동 스캔 등은 파인더갭 승인 필요
- **민감 시스템 테스트 금지**: 실제 결제 시스템, 고객 DB 직접 접근 등

## Safety 원칙 (AGENTS.md 상속)

**기본 안전장치**:
- 127.0.0.1, localhost, 로컬 Docker 격리 서비스만 무제한 테스트 가능
- 공인 IP/프로덕션 환경은 항상 **파인더갭 공식 승인**이 선행되어야 함

**이 프로젝트에 적용되는 규칙**:
- 모든 테스트는 파인더갭 대시보드의 in-scope 호스트만
- 새로운 대상/행동이 추가되면 다시 확인 필요
- 의심스러운 경우 즉시 중단, 파인더갭 지원팀에 문의

## Scope 승인 상태

- **프로그램 승인**: PENDING (파인더갭에서 확인 필요)
- **테스트 대상 확정**: PENDING (파인더갭 대시보드 스코프 확인 필요)
- **AI 작업 권한**: 파인더갭 공식 규칙 준수 시에만 자동 진행

> 이 파일의 Scope 상태가 PENDING인 동안은, 실제 테스트 전에 사람(지우님)이 파인더갭 대시보드를 확인하고 "GO" 승인을 해야 함.
